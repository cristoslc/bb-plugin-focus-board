### Style — warning

Style is solid overall: the React change matches the desktop split-control branch line for line, uses the repo's cn() helper, and comments explain the non-obvious positioning constraints; the tests follow the file's existing assertion conventions and the changelog matches the Keep a Changelog format. Three minor findings: a pre-existing block comment now contradicts the new compact split and misdescribes it as intentional, the repro script imports mkdir without calling it, and the phone viewport literal is duplicated instead of named as a constant.

**Findings:**

1. **[Medium] New compact split leaves the block comment above it stale and self-contradicting** — `components/thread-pane.tsx:843`. Before the new split wrapper, the block comment at lines 838-844 still states that the compact header keeps the icon toggle plus the standalone ellipsis menu, since there is no room for a labeled split there. That is now the opposite of what the code two hundred pixels away does, and the new comment inside the compact branch says the split applies at every width. A reader of the block comment will believe the compact standalone menu is intentional and may revert the split to satisfy it. Two descriptions of the same control, one forty lines apart, disagreeing in the same function is exactly how header behavior rot starts.
   Suggested fix: rewrite the comment so it states the read-state toggle and thread actions render as ONE split control at every width — the same grammar as the open menu: a read-state primary on the left (labeled on desktop, icon-only on compact), a hairline divider, then the attached caret opening the thread-actions menu (done, pin, snooze, archive). No floating ellipsis.

2. **[Low] Unused mkdir import in the repro script** — `scripts/screenshot/repro-markread-mobile.mjs:9`. repro-markread-mobile.mjs imports mkdir but never calls it, so nothing creates the output directory if it is deleted or when someone runs the script on a fresh clone before checking out the committed evidence folder. The repo's other driver, scripts/screenshot/shoot.mjs, imports mkdir and calls `await mkdir(OUT, { recursive: true })` for exactly this reason. The asymmetry makes the new script break where the established pattern works.
   Suggested fix: `import { writeFile } from "node:fs/promises";` and before writing: `await mkdir(OUT, { recursive: true });`

3. **[Low] Phone viewport literal duplicated twice in the repro script** — `scripts/screenshot/repro-markread-mobile.mjs:24`. The object { width: 390, height: 844, deviceScaleFactor: 2 } is written verbatim in both puppeteer.launch and page.setViewport. If one copy changes and the other does not, launch and emulation sizes silently diverge and the captured evidence is at the wrong device scale for one of them. shoot.mjs avoids this with a named VIEWPORTS constant and the comment "iPhone 14-ish"; the new script hardcodes the numbers instead.
   Suggested fix: extract a named constant `const PHONE = { width: 390, height: 844, deviceScaleFactor: 2 };` (commented "iPhone 14-ish") and pass it to both puppeteer.launch's defaultViewport and page.setViewport.

*Status note: all three findings addressed in commit 9d76801.*
