# Snooze — a snoozed thread becomes unread at a target time

## Decisions (operator, 2026-10-02)

- **Presentation**: dimmed in place. The card stays on the board, reduced opacity, with a "Snoozed · wakes <time>" chip. No new lane, no hiding.
- **Presets + custom time**: menu offers Snooze · 1 hour, Snooze · 4 hours, Snooze · Tomorrow 9am, Snooze · 1 week, and "Pick a time…" with a dialog (datetime picker).
- **CLI parity**: `bb focus-board snooze list/set/clear`, mirroring the done commands.

## Semantics

Snooze = **read now, unread later**. The set gesture marks the thread read immediately (so it stops shouting in the Unread lane) and stamps a wake record; at the target time the server marks the thread **unread** again. With dimmed-in-place, an unread card snoozed from the Unread lane therefore leaves Unread at set time and returns to Unread at wake — "stays put" means no hidden cards and no extra lane, not literally the same column.

- **Record shape**: board-owned thread plugin metadata, key `snooze` → `{ wakeAt: ISO-8601, setAt: ISO-8601 }` (the `done` / `pin` record pattern; `parseSnoozeRecord` fails loud, mirrors `parseDoneRecord`).
- **Wake**: a server-side `setTimeout` per snoozed thread, re-armed at plugin load (a daemon restart re-scans the live thread list and fires any past-due wake immediately). At wake: remove the metadata, publish `snooze-changed`, then `sdk.threads.markUnread`.
- **Existing machinery does the wake's UI work**: `markUnread` publishes `read-state-changed`; the board's existing listener restores a parked pin and un-does a Done card, exactly as any other deliberate mark-unread does.
- **Set gesture**: `snooze_set` writes the record, arms the timer, and calls `sdk.threads.markRead` so the card leaves Unread now. Re-snoozing replaces the record and re-arms.
- **Current intent beats the snooze**: any state-changing gesture on a snoozed card (menu Mark Read/Done/Unread, Archive, cross-column drop) clears the snooze record first, the same rule a pin write applies to a parked pin. Snoozed cards refuse sweep selection (both arms skip snoozed threads — the wake must resurface the thread, a sweep would archive or Done it first).
- **Pinned cards**: snoozing a pinned card runs the lane-exit path (unpin + park), so the wake's unread mark restores the pin through the existing listener.
- **Wake race**: the timer re-checks the fresh record before firing; a cleared or replaced snooze does not wake from a stale timer, and a replaced snooze's timer is always overwritten at arm.

## Server (`server.ts` + `lib/snooze.ts`)

- `lib/snooze.ts` (pure, no SDK): `SNOOZE_METADATA_KEY = "snooze"`, `SnoozeRecord { wakeAt, setAt }`, `parseSnoozeRecord`, `stampSnooze`, `presetWakeAt(kind, now)` for the four presets, `wakeSweepArming` cap helpers (`MAX_TIMEOUT_MS = 2^31-1`; longer wakes re-arm until due).
- RPC contract: `snooze_list` (record map off the live list), `snooze_set {threadId, wakeAt}` (records wakeAt as-is; the client computes presets in local time), `snooze_clear {threadId}`.
- Realtime: `snooze-changed` with `{ threadId }`; boards refetch on it (payload consumers refetch, mirroring done-changed).
- CLI: `snooze list [--json]` (id, wakeAt, overdue flag, title), `snooze set <id>... <when>` (ISO timestamp or `+<n>m/h/d` relative), `snooze clear <id>...`; both set and clear publish and re-arm timers.
- Sweep skip: sweep facts gain `snoozed`; `sweepCliEligible` excludes snoozed threads from both arms (board-side candidate functions filter the same way).

## Frontend (`app.tsx`, `components/thread-card.tsx`, `components/snooze-dialog.tsx`)

- State: `snoozeRecords` fetched on mount + on `snooze-changed`; the derived id set drives dimming and drag refusal.
- Card: chip "Snoozed · wakes <h:mm>" (Clock icon) in the meta row; dim (`opacity-50`) unless the card is already dimmed by done; drag refused while snoozed — the menu is the state-change surface.
- Menu: when snoozed, a single "Unsnooze" entry; otherwise the four preset entries plus "Pick a time…" under one divider group.
- Dialog: `snooze-dialog.tsx` — datetime-local input defaulting to tomorrow 09:00; Confirm only when the picked time is in the future.
- Done/pane/sweep props already established in app.tsx get the snooze guards bolted on where the guards' siblings live.
