# Musing: The sweep

*2026-09-25 · split from the combined done/CLI/trackers musing · depends on the Done state musing*

Marking Done is the beginning of a thread's exit, not a terminal state, so
Done needs an exit to Archived. This musing covers the interaction; the Done
tag/table it reads lives in the Done state musing.

## The decision: an arm-then-confirm sweep button, per column

Rejected first: **automatic aging** (threads marked Done ≥ N days archive
themselves on a schedule). Costs a background sweep, a setting, and the
surprise of an archive the operator didn't perform today.

Chosen: **a sweep button on the column, two-click arm-then-confirm, modeled
on delete patterns** — the operator's design, replacing an earlier
one-click-button draft:

- **First click arms.** The button activates (e.g. gains "?"), eligible cards
  highlight, and they gather at the top of their column so the blast radius
  reads at a glance. The button label extends while armed to say where the
  swept threads go: "Sweep 6 → Archive."
- **Second click performs.** Clicking again or away disarms. Nothing moves
  until the second click.
- The armed state *is* the graphical pre-sweep indication, concentrated; an
  always-on eligibility marker (tick fringe, "sweeps in N days" chip) is a
  possible refinement, not a requirement.
- Undo after the fact is bb's unarchive, already wired for the thread pane.

Decision reversal, 2026-10-01: the arm-then-confirm pattern stands, but the
idle arm's destination does not. The original draft archived long-idle
threads outright; once it ran on a real board the operator reversed it —
a quiet thread was never marked Done, and archiving it buried live context
behind a gesture that reads as "this is finished." The idle arm now marks
threads Done (same recipe as a drop on the Done column), the armed pill
reads "Sweep N → Done" there, and the fresh doneAt stamp hands the thread
to the Done arm, which archives it after `doneArchiveDays`. The exit is
staged: idle → Done → Archive. The Done arm's destination is unchanged.

Settled operator decisions:

- **Separate arms for each column.** The Done column and the Awhile-ago
  column each get their own sweep button, armed and fired independently.
- **Arming captures an explicit list.** The set of cards is fixed at arm
  time; a late arrival (a thread crossing the threshold, a live update) does
  not join an already-armed sweep — it becomes eligible for the next arm.
  The second click archives exactly what was highlighted, nothing else. This
  removes the mid-arm race entirely.
- **The sweep also applies to the "Awhile ago" column.** The idle-aging
  bucket (newest-first idle buckets in the Attention grouping) is the same
  "old and quiet" signal from the other side: a thread idle for ages and not
  Done should be sweep-eligible too, or the sweep only cleans up the threads
  you bothered to mark. The sweep is "archive old Done + long-idle."
- **Threshold setting**: `doneArchiveDays`, default 7. The button only ever
  proposes what automatic aging would have done, so graduating to a fully
  automatic sweep later is a settings change plus a scheduler, not a
  redesign.
- **Override safety valve confirmed.** Per-card keep-past-threshold stands,
  and because the sweep widens to long-idle cards, it applies to those too,
  not just Done ones. Without it, a sweep that archives your reference
  thread once is the last time anyone uses the feature.

## Still open

- Aging basis when Done is a tag: lean toward the `done:` stamp date the card
  already renders ("Done a week ago" is about your attention, not the
  thread's last flicker); confirm the sidebar view exposes what's needed.
- The sweep's CLI surface, if any — covered in the CLI musing.
- Whether the count in the armed button recomputes live or freezes with the
  captured list (freeze matches the explicit-list decision; unconfirmed).
- Threshold and idle-bucket semantics for the Awhile-ago arm (which idle
  bucket counts as "long-idle," and whether it shares `doneArchiveDays` or
  gets its own setting).
