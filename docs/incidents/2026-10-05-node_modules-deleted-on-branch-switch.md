# Incident: main-checkout node_modules directory deleted during branch restore

- **Date:** 2026-10-05 (thread thr_qs29yvc9a3, focus-board repo)
- **What happened:** During the linked-issue-chip live verification, the main checkout (`/Users/cristos/Documents/code/bb-plugin-focus-board`) was on a detached feature-branch commit that carried an accidentally committed `node_modules` symlink blob. `git restore node_modules` (attempted to clear the resulting "deleted" index entry) plus `git checkout dev` removed the real, gitignored `node_modules` directory that other worktrees symlink into.
- **Impact:** Dependency tree loss in the main checkout only. No source, no user data, no credentials affected; bb plugin serving was unaffected.
- **Detection:** `ls node_modules` failed immediately after the branch switch back to `dev`.
- **Remediation (completed):** `npm ci --no-audit --no-fund` from the committed `package-lock.json` restored 204 top-level packages; `npx tsc --noEmit` passes again in the main checkout.
- **Root cause:** The feature branch accidentally contained a tracked `node_modules` symlink (committed during Unit A setup); `git restore` across a type change (symlink ↔ real directory) deleted the directory.
- **Fix applied on branch:** Commit `3296cd4` "Chore: drop accidentally committed node_modules symlink (deps stay untracked)" removes the blob from the feature branch, so a future checkout of it cannot reproduce this.
- **Prevention:** Never `git restore`/`checkout` across a path whose working-tree type differs from the index (symlink vs directory); when a committed artifact shadows a real directory, `git rm --cached` first and only then switch branches.
- **Runbook:** None needed; the recovery is the two commands above.
